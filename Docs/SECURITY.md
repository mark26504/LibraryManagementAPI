# Security

## Authentication

- **Access token**: JWT (Bearer), 15-minute lifetime; claims: `sub`, `email`, `role[]`;
  issuer/audience validated; signing key from configuration (User Secrets / env), never in repo.
- **Refresh token**: opaque token in an **HttpOnly** cookie scoped to `/api/v1/auth`,
  sent with `Secure`/`SameSite` per environment; **rotated on every refresh**;
  revoked on logout, on password reset, and when the account is disabled.
- Refresh/revoke endpoints accept an empty JSON body `{}`; the cookie is the only credential.
- Login of a disabled account → 403; invalid credentials → 401 (single generic message).

## Authorization

Roles: `Admin`, `Librarian`, `Member` (ASP.NET Core Identity roles).

| Area | Read | Write |
|---|---|---|
| Users management | Admin | Admin (self-role/self-status changes forbidden; last active admin protected) |
| Catalog (authors/categories/books) | Public | Librarian+ |
| Book covers | Public (static) | Librarian+ |
| Borrow (create / my list / my return) | Member (self) | — |
| Borrowings staff list / overdue / any return | Staff (Librarian+) | Staff |

## Email Flows

- Confirmation & reset tokens are generated by Identity and delivered **only via email**;
  no endpoint ever returns them.
- Tokens are single-use; `confirm-email`, `forgot-password`, `reset-password` return
  generic messages to prevent account enumeration.
- Successful password reset revokes all active refresh tokens for the user.

## Rate Limiting & CORS

- Global per-IP limiter + stricter limiter on `/auth/*`; exceeded → 429 with `Retry-After`.
- CORS: Angular origin(s) only, credentials enabled, `Retry-After` exposed.

## Uploads (book covers)

- Controller enforces: extension whitelist `.jpg .jpeg .png .webp`, matching MIME type, max 5 MB.
- Service enforces (defense in depth): folder whitelist (`uploads/books`), extension whitelist,
  server-generated `Guid` filenames (client names never touch disk),
  traversal-safe delete (resolved path must stay inside `wwwroot`).
- Files served statically from `wwwroot`; URLs returned as `/uploads/books/{guid}.{ext}`.

## Error Hygiene

- All errors → Problem Details (`type, title, status, detail, instance, traceId`, plus
  camelCase `errors` dictionary for validation).
- No stack traces, no SQL text, no Identity internals in responses.
- `traceId` correlates with Serilog logs.

## Secrets & Dev-Only Relaxations

- Secrets (JWT key, connection string, SMTP credentials) live in User Secrets / environment
  variables; `appsettings.json` carries no credentials.
- Dev-only: Postman SSL verification off for the localhost self-signed certificate;
  localhost CORS origins; seeded demo accounts. None of these apply to production config.
